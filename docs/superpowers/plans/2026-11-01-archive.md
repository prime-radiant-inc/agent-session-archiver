# Simple Archive Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans or superpowers:subagent-driven-development to implement one task at a time. Check boxes record completed work.

**Goal:** Preserve native agent traces across hosts with SSH push/pull and ordinary files.

**Architecture:** Discover sources, transfer changed files through staging, then safely incorporate them. Push/pull share host configuration and collection logic. Manifests retain provenance; viewers interpret sessions.

**Tech Stack:** Go, SSH, rsync, TOML and JSON. Optional sqlite3 CLI only for database-backed harnesses.

**Spec:** [Simple design](../specs/2026-11-01-archive-design.md)

## Global constraints

No sharding, archive database, custom protocol, session graph, transaction journal or
new service. Never propagate deletions or replace a transcript with a truncated or
conflicting source. Source identities and initial archive placement stay stable.
Support Linux/macOS and the five harnesses in the spec. Use synthetic public fixtures.

## Review focus

- Same native IDs in multiple roots must not collide (Task 1).
- A growing or disappearing source must not corrupt committed data (Tasks 2–3).
- Interruption between file and manifest publication must be recoverable (Task 3).
- One offline host must not prevent the remaining hosts from collecting (Task 4).
- Database reset must not remove previously captured sessions (Task 5).

## Structure

Start with configuration, harness discovery, archive writing and SSH orchestration.
Use a thin CLI entry point and adjacent behavior tests. Determine package boundaries
from the working code, not a predetermined set of interfaces. Keep the raw archive
format in docs/archive-format.md and usage/recovery in docs/operations.md.

### Task 1: Configuration and naming

- [x] Write failing tests for the spec's TOML: two hosts, three Claude roots, default
  directories, explicit replacement, empty/duplicate roots, and unlisted harnesses.
- [x] Implement one host record for both push and pull. Expand home paths on the
  source. Validate unique host selectors and stable user/host identities.
- [x] Test repository/worktree grouping, nonrepository path collisions, identical
  native IDs across roots, and retaining the first archive placement after a remote
  changes. Also test Codex sessions/ to archived_sessions/ movement retaining identity,
  while a changed installation root creates a separate source. Implement the spec's
  identity tuple, sanitized bounded names and small provenance manifests.
- [x] Run the tests, document config and naming, and commit.

### Task 2: File collection

- [x] Write failing synthetic tests for Claude, Codex, Pi and Evener, including known
  companions, compressed files, missing roots and malformed message content.
- [x] Implement metadata-only discovery. Preserve raw bytes; do not resolve ancestry
  or join sessions. Send a metadata inventory to the archive; compare it with committed
  source size/mtime hints in manifests and return the requested file list. Test this
  with no state on the source so both push and pull work without a source catalog.
- [x] Test append during reading and mutable-file changes. Prepare stable copies of
  changed files only; pin lengths for append-only sources and reject unstable mutable
  captures. Copy from one open descriptor, reject short reads, and test truncation
  and pathname replacement during capture. --full bypasses metadata shortcuts. No
  persistent inventory database.
- [x] Run tests, document native root meanings and temporary-space needs, and commit.

### Task 3: Destination writing and verification

- [x] Write failing tests for new capture, valid append, shrinkage, conflicting prefix,
  missing source, unsafe path, concurrent writers, disk-full and interrupted publication.
- [x] Implement destination staging, a host writer lock, checksums/prefix validation,
  temporary files and rename. Update manifests last. Retry repairs older metadata
  around intact newer files without a journal. Keep intended manifests/hashes in
  destination staging until completion; recover completed pending transfers before
  new discovery. Test interruption followed by deletion of all fixture sources,
  recovery from staging, and successful verify. Never infer deletion from absence.
- [x] Implement verify using the archive alone. Test that deleting fixture sources
  leaves verification passing, and that corruption is reported.
- [x] Run tests with real temporary directories and injected I/O failures, document
  recovery/failed staging cleanup, and commit.

### Task 4: SSH push/pull and host lists

- [x] Write failing integration tests using disposable real localhost SSH and rsync:
  push/pull byte equivalence, remote ~ expansion, interrupted transfer, hostile path
  characters, multiple roots and one unavailable host among healthy hosts. Assert an
  unchanged second run skips payloads in both directions and switching from push to
  pull against the same archive needs no source-side state.
- [x] Implement fixed remote discovery/preparation/incorporation helpers, safely passing
  structured configuration. Use rsync into staging; no archive deletion or in-place
  archive writes. All connections originate at the command's initiating machine.
- [x] Implement the spec's push, pull, pull --all and verify commands, --config and
  --full. Run hosts sequentially. Exit 0 for complete success, 1 for collection or
  transfer failures, 2 for invalid arguments/config. Report partial failures precisely.
- [x] Run real SSH tests. Document SSH dependencies, credentials, scheduling and
  retry behavior; commit.

### Task 5: OpenCode capture

- [x] Write failing tests with a real WAL database, concurrent writer, source reset,
  identical snapshots and missing sqlite3. File-only collection must work without it.
- [x] Invoke sqlite3 online backup safely, store distinct captures under _sources,
  and associate native sessions with snapshots. Retain previous captures without
  introducing a generalized object store or automatic pruning.
- [x] Run tests; document storage growth and dependency requirements; commit.

### Task 6: End-to-end proof and first rollout

- [x] Run go test -race ./... and go vet ./..., plus the real SSH gate. Add Linux/macOS
  CI checks and a Linux SSH integration job using only synthetic data.
- [x] Measure discovery and changed/unchanged collection for 100,000 synthetic traces.
  Optimize measured bottlenecks only; full changed-file transfer is acceptable initially.
- [x] Demonstrate one disposable AgentsView import and distinguish unsupported import
  shapes from archive failures. No general viewer-adapter subsystem.
- [ ] Capture and verify this host into a new archive outside working harness homes.
  Keep enrollment config and traces out of git. Test deletion only with fixtures.
  Enroll remote hosts only after Jesse identifies them.
- [ ] Review the branch, publish accurate operating instructions and report counts,
  failures, verification, benchmark results and remaining viewer limitations.
