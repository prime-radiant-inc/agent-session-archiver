# Agent Session Archiver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve native agent traces on an archive server through SSH push and pull, with viewer-independent recovery.

**Architecture:** A source collector and an archive receiver share one transfer protocol. Archive manifests and original files are authoritative; catalogs and viewer import views are disposable. Source deletion never removes committed archive content.

**Tech Stack:** Go, system OpenSSH, SHA-256, JSON manifests, and SQLite online backup for shared database sources. Use a maintained SQLite driver exposing online backup; pin the selected version and document its Linux/macOS build requirements in Task 5.

**Spec:** [Approved design](../specs/2026-11-01-archive-design.md)

## Global Constraints

- Use ordinary files, organized by user, host, project, harness, then trace directory.
- No sharding initially, even for projects with 100,000 traces.
- Support push and pull over SSH with one implementation.
- Never propagate source deletions.
- No automatic garbage collection in the first release.
- Both endpoints need the tool; automatic installation on remote machines is outside the initial scope.
- Linux and macOS are supported; use synthetic fixtures only in this public repository.
- Archive success and viewer import success are separate statuses.
- The initial deployment excludes Hermes. Missing or unsupported sources must be reported.

## Review Focus

- Host aliases and sanitized names collide: retain separate authorized identities (Tasks 1 and 6).
- Source truncates or rewrites during transfer: retain the last committed archive and report conflict (Tasks 2 and 4).
- Disk fills between file and manifest publication: recovery retains previously committed bytes (Task 2).
- Protocol output or a source path is malicious: bounded decoding and no execution or path escape (Task 6).
- A shared database loses sessions after reset: older referenced captures remain recoverable (Task 5).

## File Structure

- `cmd/agent-session-archiver/main.go`: CLI entry point; no collection logic.
- `internal/archive/{identity,manifest,store,verify}.go`: archive naming, contracts, publication, verification.
- `internal/collect/{collector,claude,codex,pi,evener,opencode}.go`: source adapters and inventory.
- `internal/catalog/catalog.go`: disposable discovery and transfer checkpoints.
- `internal/snapshot/sqlite.go`: consistent database backup.
- `internal/transfer/{protocol,session,ssh}.go`: shared sender/receiver and SSH orchestration.
- `internal/view/agentsview.go`: disposable native-layout view.
- `internal/cli/run.go`: commands, configuration, summaries and exit status.
- Adjacent `*_test.go`: behavior tests; `tests/ssh_test.go`: real SSH integration.
- `docs/{archive-format,operations,development}.md`: evergreen format and operational documentation.
- `.github/workflows/test.yml`: Linux/macOS checks using synthetic inputs.

## Shared Contracts

Define these in Task 1; later tasks consume them rather than inventing alternatives.

`archive.Identity` contains `User`, `Host`, `Project`, `Harness`, and `TraceID` strings.
`archive.Member` contains `Path`, `SHA256` strings, `Size int64`, and `Mode UpdateMode`.
`UpdateMode` distinguishes `Append`, `Mutable`, and `Immutable`; never infer mode from a file extension alone.
`archive.Reference` contains `SourceID`, `CaptureID`, and `MemberPath` strings.
`archive.Manifest` contains `FormatVersion int`, `Identity Identity`, original source metadata,
parent trace IDs, timestamps, `Members []Member`, and `References []Reference`.
`archive.SourceManifest` identifies a shared capture and lists members and hashes.
`collect.Candidate` contains the manifest metadata, local file members, and shared source dependencies.
`collect.Config` contains enrolled identity, enabled harnesses, and explicit roots/overrides.
`collect.Report` contains discovered/captured counts and per-source failures; a partial result is never deletion authority.

### Task 1: Archive identity and manifest contracts

**Interfaces:** `ProjectIdentity(remote, commonDir, cwd string) (string, error)`; `ValidateManifest(Manifest) error`; `TracePath(Identity) (string, error)`.

### Task 2: Durable local archive publication

**Files:** `internal/archive/store.go`, `internal/archive/verify.go`, adjacent tests.

**Interfaces:** `Open(root string) (*Store, error)`; `(*Store).Publish(ctx context.Context, manifest Manifest, files map[string]io.Reader) error`; `(*Store).Verify(ctx context.Context) (VerifyReport, error)`. Define `VerifyReport` with checked-file counts and per-file failures. The store owns namespace locks and staging.

- [ ] Write failing tests `TestPublishAndRecover`, `TestMissingSourceRetained`, `TestAppendConflict`, `TestInterruptedPublish`, `TestConcurrentPublish`, `TestUnsafeArchiveSymlink`, and `TestDiskFullPublication`. Assert manifest hashes match raw bytes, conflicts preserve old bytes, readers see committed manifests, concurrent writers cannot interleave publication, and faults at each publication boundary preserve the previous committed state.
- [ ] Run `go test ./internal/archive`; confirm the tests fail for absent publication behavior.
- [ ] Implement staging, prefix verification, bounded file copies, durability ordering and atomic manifest publication. Mutable companions use recoverable replacement with a transaction journal; recovery completes or rolls back an interrupted publication before accepting a new writer. Never overwrite committed raw bytes in place. Successful completion cleans temporary superseded companion copies, not archived transcripts.
- [ ] Run `go test -race ./internal/archive`; verify recovery by reopening real temporary directories after injected I/O faults. Commit.

### Task 5: Shared sources and OpenCode snapshots

**Interfaces:** `snapshot.SQLite(ctx context.Context, source, destination string) error`; `(*Store).PublishSource(ctx context.Context, manifest SourceManifest, files map[string]io.Reader) error`. Trace publication checks that referenced captures already exist and verify.

### Task 6: SSH push and pull using one transfer engine

**Files:** `internal/transfer/protocol.go`, `session.go`, `ssh.go`, adjacent tests, `tests/ssh_test.go`.

**Interfaces:** `Send(ctx context.Context, rw io.ReadWriter, cfg collect.Config) (collect.Report, error)`; `Receive(ctx context.Context, rw io.ReadWriter, store *archive.Store, allowed Namespace) (collect.Report, error)`; `Namespace` specifies locally authorized user/host. `SSH(ctx context.Context, host, mode string) (io.ReadWriteCloser, error)` starts the fixed internal command and passes variable configuration inside the stream.

- [ ] Write failing protocol tests for incompatible versions, oversized/truncated frames, unsafe member paths, unauthorized identities, disconnect/retry, and bad checksums. Write `TestPushPullEquivalent` against a disposable real localhost sshd: both directions must produce identical manifests/raw hashes, with only the initiating side holding connection credentials.
- [ ] Run `go test ./internal/transfer` and `go test ./tests -run TestPushPullEquivalent`; absent SSH dependencies must produce an explicit setup failure in the integration gate.
- [ ] Implement one framed bidirectional protocol: bounded control records, length-delimited bytes, per-file hashes, explicit commit acknowledgments. Initial limits: 1 MiB per control record and 1 MiB per data chunk; stream larger files. Reject hostile remote names beginning with options. Invoke only fixed remote commands, with no paths interpolated into the remote shell. Partial files remain staged; retry can restart an incomplete file without compromising committed data.
- [ ] Run unit and SSH integration tests, including shell metacharacters in source filenames and a host identity collision. Capture child process exit status and stderr separately from protocol bytes. Commit.
